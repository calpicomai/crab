# Software commissioning acceptance — 2026-10-28

Owner authorizes reviewed, tested successive software increments and conditional
merge, not physical deployment, actuators, device installation, real recording,
credentials/security changes or paid compute. The endpoint is a self-contained
Codex CLI commissioning handoff with explicit hardware gates, not a claim of
autonomous navigation, adaptive balance or a trained policy.

## Work sequence and ownership

1. Root: merge verified bridge47 and assess post-merge main CI.
2. Root: preserve/rebase Lab onto merged main, add maintenance/CI/evaluation
   gates, independent review, publish/test/merge if eligible.
3. Fresh dashboard worker: correlated observations/UI only in its isolated
   branch. Root integrates, independently verifies and reviews control impact.
4. Root after those units: diagnose lifecycle/readiness gaps, implement bounded
   fixes with fault-injection tests; keep old control guards and one owner.
5. Root: evaluate all gates, produce the commissioning bundle and next bounded
   perception/learning proposal. Continue recoverable software issues; stop only
   at a real owner/platform/physical dependency and identify the exact gate.

No gate is closed by prose, an agent claim or a screenshot alone. Record exact
commands/commits and results, distinguish CI software platforms from owner's
hardware, and leave missing evidence open. Independent reviewers do not operate
devices or write approvals on GitHub. Main/PR CI must reach terminal outcome.
